**Method.** Full read of every file above against SPEC §6.3, §6.5, §6.6, §6.9, §7, §10, ARCHITECTURE.md §5 (security invariants) and API.md. Grep sweeps for `console.*`, `managedLog`, `dangerouslySetInnerHTML`, `localStorage`, `sessionStorage`, `href`, `managedReauthAt`, `migrate`, `DATABASE_URL`. Two ethers v6 internals were verified in `backend/node_modules/ethers` because findings depend on them: `HDNodeWallet.deriveChild` propagates `this.mnemonic` to children (`lib.commonjs/wallet/hdwallet.js:247`), and `makeError` serialises every `info` field (including raw signed transactions and RPC payloads) into `err.message` (`lib.commonjs/utils/errors.js:114`). Dependency advisories checked with `npm audit --omit=dev` (read-only) in `backend/` and `frontend/`. Nothing was run against a database; `backend/.env` was not read.

Severity scale: **High** = key/mnemonic exposure, fund loss without admin error, or auth bypass. **Medium** = fund loss or integrity loss that needs a second condition (admin action, environment, timing), or an explicit SPEC/ARCHITECTURE invariant broken. **Low** = hardening, information quality, defence in depth. **Info** = scope or documentation.

## 3. Per-threat verdicts

1. **Key at rest — OK.** `keyVault.ts`: AES-256-GCM, random 12-byte IV per record (one encryption per pool, collision risk negligible), 16-byte tag with `authTagLength` set on both sides, AAD = pool id (ciphertext cannot be moved between rows), strict base64/length check on `WALLET_ENCRYPTION_KEY`, `key_version` compared before decrypting, wrong/missing key → `KeyVaultError` → 503 `KEY_VAULT_UNAVAILABLE` (never the raw crypto message). `POOL_SELECT` never selects the `mnemonic_*` columns; only `pools.getSecret` does, and it is called only from `createPool`/`revealMnemonic`/`generateWallets`/`vaultPort`. `scripts/managed/gen-key.ts` prints only the key. Missing key: routes 503, workers not started, `/health` reports `keyVault: "missing"`.
2. **Key in memory — Finding SR-06 (Low).** Plaintext exists in `createPool`, `revealMnemonic`, `generateWallets`, `deriveSigners`, as specified. It also lives inside the derived `HDNodeWallet` signers for the job's lifetime (ethers keeps `mnemonic` on children) and the `mnemonic = ""` lines do not wipe anything. No path assigns it to a logger, request, closure that outlives the job, or error object (`fromPhrase` failures are caught and replaced by a fixed message; ethers redacts the phrase in its own assertion errors).
3. **Logs — Findings SR-05, SR-09 (Low), SR-13 (Info).** All `managed/` log calls go through `managedLog` → `redact()` (`console.*` appears only inside `redact.ts` and the unused `ports.consoleLogger`). `redact()` covers `mnemonic`/`ciphertext`/`privateKey`/`password` keys, 12/24-word phrases, 64-hex tokens, Error objects (name/message/stack/code only — ethers `info`/`transaction` *objects* are dropped), Buffers, Maps, Sets, cycles. Gaps: hex strings longer than 64 (signed raw tx in ethers messages); 15/18/21-word phrases (only matter if a key-less string ever carried one — none found). `index.ts` logs only `err.message` of env-validation errors (echoes the offending env *value*, e.g. a malformed `MANAGED_TOPUP_BUFFER_WEI`, never a secret). `migrate.ts` logs file names and pg messages, never `DATABASE_URL`. Reveal endpoint response is never logged (no body logger in the app).
4. **API responses — Finding SR-04 (Medium).** Verified route by route against API.md: `toPool` omits `ownerUserId` and the secret columns; `stripToken` on `GET /pools/:id/wallets`, `PATCH /wallets/:id`; `viewToken` appears in `GET /wallets/:id` and `POST …/rotate-view-token` (allowed) and, via `viewUrl`, in the wallet list (not allowed). `toJob` spreads `TransferRecord` (no `idempotency_key`, no secrets). `createPool` never echoes the mnemonic (`imported: Boolean(...)` only). Public view returns exactly the documented fields plus `explorerUrl`; no pool id, name, index, holder, or other wallet. Error translator never returns raw `err.message` for unknown errors. `/health` additive `maxWalletsPerPool` is harmless.
5. **CSV export — OK.** Columns `index,address,label,holder_name,holder_email,status,<symbols>`; no keys, no tokens, no ids beyond the derivation index. `csvCell` prefixes `=+-@\t\r` with `'` and RFC-4180-quotes `",\r\n`; applied to every cell including token-controlled headers. `text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="pool-<uuid>.csv"` (uuid validated, no header injection), `Cache-Control: no-store`, audited. SR-07 (duplicate symbol headers) is a quality note.
6. **View tokens — OK (SR-10 Low on the limiter environment).** `randomBytes(32).hex` (256 bits), `UNIQUE (view_token)`, regex-gated then exact-match lookup (DB equality is not constant-time, but 256-bit random tokens make timing enumeration infeasible), rotation replaces the token atomically and is re-auth gated and audited, `DISABLED` wallet or `ARCHIVED` pool → same generic 404 as unknown, `Cache-Control: no-store`, `express-rate-limit` 60/min/IP (`standardHeaders`, custom JSON body) applied before token parsing. Payload: label (admin-chosen; can carry a holder's name by choice), address, network, balances, last 50 visible deposits with sender addresses, explorer URL built from a constant base. Hidden tokens excluded. Frontend route `/w/:viewToken` is outside the auth shell by design.
7. **Re-auth — OK.** 10-minute window (`REAUTH_WINDOW_MS`), stamp `<= now` guard, `verifyPassword` uses `crypto.timingSafeEqual` on equal-length buffers, OAuth-only users never match, 5 failures / 15 min per user (in-memory, per process — acceptable because the caller already holds an ADMIN session), `clearReauthFailures` on success. `managedReauthAt` is written only by `stampReauth` (grep confirms) and only after a successful password check. Session fixation: passport 0.7 `req.login` regenerates the session id, so a pre-planted stamp cannot survive login; `/logout` calls `req.logout` + `session.destroy` + `clearCookie`, so the stamp dies with the session. Frontend keeps `validUntil` in a module variable only; the password state is cleared after submit; nothing persisted.
8. **Authorization — OK.** `router.use(requireAdmin)` is the first middleware of the admin router (before `/health`); `keyVaultGuard` after `/health`; `requireRecentReauth` on `POST /pools`, `reveal-mnemonic`, `rotate-view-token`, `POST /transfers`, `/transfers/sweep`, `/transfers/:id/retry` — exactly the API.md **reauth** set. All ids pass `requireUuid` (including `/transfers/:id` and `/retry`, inside the service). Pools are admin-global by design (ARCHITECTURE §5.6) and every consumer is consistent with that; cross-pool `walletIds` in a sweep are filtered by `w.pool_id = $1`; a transfer uses the wallet's own pool. No migrations endpoint exists (`migrate.ts` is CLI-only). The public router cannot enumerate: one route, token-only, generic 404.
9. **Input validation and SQL — OK.** Every query uses placeholders; dynamic `SET`/`WHERE` columns come from fixed maps (`COLUMNS`) or fixed condition strings; `escapeLike` + `ESCAPE '\'` on all four `ILIKE` operands; `clampLimit(…, 500)`/`clampSkip` on every list; `optionalInt` rejects negatives and non-integers; `network` enum, `status` enums, `asset` = `native` or checksummable address lowercased, `toAddress`/`tokenAddress` checksummed by `getAddress`, amount regex `^\d+(\.\d+)?$` then `parseUnits` with the token's decimals, `> 0` enforced; `toWei` regex guards every NUMERIC write; `idempotencyKey` ≤ 200 chars; `count` positive integer and capped by `MANAGED_MAX_WALLETS_PER_POOL` atomically in `reserveIndexes`; query params that arrive as arrays (`?search[]=`) fail the `typeof` checks. `holderUserEmail` is a validated string before `User.findOne` (no operator injection).
10. **CSRF posture — Finding SR-01 (Medium).** Production `sameSite: "none"` + `express.urlencoded` + no content-type/origin check = simple-request CSRF on every state-changing POST. JSON content type alone would suffice only if enforced. Residual after the fix: CORS `hostMatchesAllowed` ignores scheme and port (pre-existing), so an `http://` or alternate-port origin on the allowed host passes preflight; GET routes are read-only.
11. **Transfer engine — Findings SR-03 (Medium), SR-08 (Low), SR-12 (Info).** Idempotency via `UNIQUE (idempotency_key)` with `ON CONFLICT DO NOTHING`; pick uses `FOR UPDATE SKIP LOCKED` and commits before any chain I/O; restart recovery is receipt-first for any stored hash and re-queues jobs with nothing broadcast; retry clears the transfer hash only after `REVERTED`, keeps it after `TIMEOUT`, keeps the top-up hash always; `MAX_ATTEMPTS` enforced both in the API (`attempts >= max`) and the worker (`attempts > max` after the pick increment); destination validated (address, not zero, not the child) in the pure planner and re-checked at execution; sweeps only enumerate `balance_wei > 0` pairs of ACTIVE wallets of the requested pool, hidden tokens excluded, default destination = master; master reserve = top-up gas + buffer; native sweep never tops up; gas limit = ceil(1.2×estimate) capped by `MANAGED_MAX_GAS_LIMIT` with `GAS_LIMIT_EXCEEDED` when the raw estimate exceeds the cap; gas price clamped to `[min,max]` gwei; nonces from `pending`, single loop; signer addresses are checked against the stored master/child before signing; timeout keeps the hash. Gap: the hash is persisted only after a successful broadcast call, so an ambiguous failure plus retry can double-send (SR-03).

## 4. Residual risks accepted (with reason)

- **Timing of the view-token DB lookup** is not constant-time: 256-bit random tokens, generic 404, and the per-IP limiter make remote timing enumeration impractical.
- **Lockout and rate-limit state are per process.** Horizontal scaling multiplies both limits by the replica count; the re-auth lockout is behind an ADMIN session anyway. Revisit if replicas > 2 or if the public page becomes a target (store in Postgres or Redis).
- **Spam / phishing tokens on holder pages until hidden** — accepted in SPEC §10; SR-07 reduces the spoofing surface. Discovered tokens default to visible by product decision.
- **Holder-page label can carry a holder's name** if an admin labels wallets that way; the link is a capability the holder already owns. Document in the runbook.
- **`mnemonic = ""` is cosmetic** (strings are immutable in V8); the process memory of a Node service holds pool secrets while a job runs. Mitigated by SR-06 narrowing it to private keys and by the existing pod/secret hygiene (k8s secret for the key).
- **Signed-but-unbroadcast transactions** could in principle be replayed by someone with log access; the tx is the intended transfer and nonce-bound. SR-05 removes them from logs anyway.
- **CORS host matching ignores scheme/port** (pre-existing `hostMatchesAllowed`); after SR-01 the managed routes no longer rely on CORS alone.
- **BSC gas-price floor changes** could leave a `TIMEOUT` job with a never-mined hash; SR-03 step (3) adds the mempool check that lets the worker move on safely.
- **`shutdown()` not awaiting the worker** (SR-12) is covered by the receipt-first recovery once SR-03 stores hashes before broadcasting.

## 5b. Imported wallets (2026-10-22, migration 0004)

Pools can now hold IMPORTED wallets: a distribution session's existing wallets
with their own private keys. Controls:

- Keys never pass through the browser: the server rebuilds them from the
  session's stored seed or `output/wallets.csv` and accepts a key only if it
  reproduces the wallet's address. Only the session's owner can import it, and
  the import route requires a fresh re-auth.
- Each key is stored AES-256-GCM encrypted under `WALLET_ENCRYPTION_KEY` with
  AAD `managed-wallet:<walletId>`, so a ciphertext cannot be moved to another
  row. `key_*` columns are never mapped into API responses; audits record
  counts only.
- The worker decrypts an imported key only for the job it signs, and checks the
  derived address against the row before broadcasting (same check as DERIVED).

Accepted change of invariant: for IMPORTED wallets the pool secret is **not**
the backup. Their keys are recoverable only from the session's seed / key files
or from the encrypted column (which needs `WALLET_ENCRYPTION_KEY`). The import
dialog states this, and imported rows are tagged in the wallet table.
